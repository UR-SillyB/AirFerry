## v1.2.9

本版新增**网页接收端单文件版**（Chrome/Edge 双击即用），并合入 Windows 分段接收修复与 Python 发送端。传输协议未变，与 v1.2.0–v1.2.8 的 descriptor v5 完全兼容。

### 网页接收端单文件版

- 新增 `airferry-receiver-web-standalone-v1.2.9.html`（约 6.4 MB）：Vite IIFE 主 bundle + `receive`/`qr-decode` 两个 module Blob Worker + `transfer_engine`/zstd/lzma/FAST ZXing/`zxing_reader` 全部 WASM 内联，**双击在 `file://` 下即可用摄像头或屏幕捕获接收**，无需静态服务器。
- 构建入口：`cd apps/web && npm run build:receiver:standalone` → `dist-receiver-standalone/index.html`；`scripts/build-all.sh web` 自动按版本命名复制到 `dist/`，`pack_dist` 也按 warn 模式补回。
- FAST 后端在 Blob 模块内通过 `wasmBinary` + `locateFile`（wasm Blob URL）加载，避免 `import.meta.url` 无法作为相对基址；兼容后端 `locateFile` 同样返回 wasm Blob URL。
- 浏览器限制：Chrome/Edge 已验证；Safari/Firefox 的 `file://` 摄像头行为尚未验证。手机场景仍建议使用 HTTPS/localhost 的多文件版（`airferry-receiver-web-v1.2.9.zip`）。
- 网页发送端已有的 `airferry-sender-web-standalone-v1.2.9.html` 继续随 `build_web` 产出。

### Windows 分段接收修复（#8）

- 段存档后换入的新 `ReceiverSession` 不再重新初始化屏幕上残留的上一段：`CompletedSegmentTracker` 记录已存档子会话 id，`OnDecoded` 在 ingest 前丢弃其回放帧。
- 持续接收模式同样记住成功/重复保存的会话，保存失败时不记，保留幂等归档重试。
- 新增 4 项跨平台单测；`dotnet test` 118 项通过。

### Python 发送端（独立版本 0.1.0）

- 新增 `apps/python`：通过 PyO3 复用 Rust RaptorQ/帧协议/QR 渲染，Pillow + 管道 FFmpeg 输出 H.264 MP4；支持 Raw/Zstd/XZ、单码/四码、descriptor v5 分段、进度回调与四平台 CI。详见 `docs/build-python.md`。
- 该包版本独立于 App/扩展，尚未发布 PyPI。

### FAST ZXing-C++ 构建修复

- `core/zxing-decoder/link-wasm.sh` 显式导出 `HEAPU8,HEAPU32`（worker 依赖 `Module.HEAPU8/HEAPU32`），并改用 `em++` 链接 C++ 异常运行时，兼容 Emscripten 4+/6.x。
- 修复后单文件接收端实测 `fast=true`（Y 平面路径），不再静默回退 compat。

### 验证

- Chrome 153 + 假摄像头（`--use-file-for-fake-video-capture`）灌入 Python 发送端生成的二维码视频，单文件接收端在 `file://` 下完整恢复 19.5 KiB 文件，CRC 校验通过，FAST 后端为 `fast=true`。
- `cargo test`（核心三 crate）全绿；`dotnet test` 118 项通过；Python 20 项 + 慢速 v5 用例通过；本地 sdist/隔离 wheel 构建通过。
- 网页发送端、网页接收端多文件版构建通过；`node --test apps/sender/scripts/test-build-wasm.cjs` 2 项通过。
