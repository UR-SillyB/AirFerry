# AirFerry v2 版本升级计划（架构瘦身 × AF2 协议合并版）

> 状态：待执行
> 日期：2026-08-16
> 来源合并：`todo/architecture-slimming-plan.md`（v3 终版，已删除）+
> `docs/protocol/AF2-PROTOCOL-INDEPENDENT-FABLE.md`（AF2 协议冻结候选）
> 总原则：**每阶段可独立发布、可回滚**（仓库约 4 天一版，不允许长活分支）；
> 瘦身步骤为 AF2 铺路，凡是 AF2 落地后会被整体替换的 v1 构件，不再为其做深度重构。

## 0. 合并裁定：旧瘦身计划各步骤的去向

| 旧步骤 | 去向 | 理由 |
|---|---|---|
| 1 基线锁死（golden vectors + version check） | **保留，扩容**（→ 阶段 A） | AF2 的三端一致性同样靠它；v1 fixture 保留到 v1 删除为止，AF2 fixture 新增 |
| 2 删除死代码（assembler/resume） | **保留**（→ 阶段 A） | `resume.rs` 在 AF2 中也明确不做符号级持久化，纯赚 |
| 3 快照化 FFI | **保留，前移**（→ 阶段 B） | AF2 §16 本就要求单一 Receiver Snapshot ABI；先在 v1 上打通三段式迁移机制，AF2 只换 schema |
| 4 WASM 单轨化 | **保留**（→ 阶段 B） | 与协议无关，纯构建收益 |
| 5 零拷贝 ContentManifest | **废弃** | ETTEXT/ETBUNDL 解析器整体将被 AF2 Manifest Entry 替代，为将死代码投资 300~600 行重构是浪费；三端现有 parser 原地不动，随 v1 一起删除 |
| 6 三端控制器拆解 | **保留，重定位**（→ 阶段 E 前置） | 拆解出的 ReceiveCoordinator 正是 AF2 接收状态机的落位层；仍 Windows 试点 → Android → Web |
| 7 前端 package 合并 | **保留**（→ 阶段 B） | 与协议无关 |
| 8 Vite 替换 Plasmo | **保留，降级为可选尾项**（→ 阶段 G） | 净减有限且风险高，不阻塞 AF2；有版本压力时可无限期搁置 |
| 9 FAST-only 强制 | **保留**（→ 阶段 B） | 接收端性能是 AF2 实测的前提 |
| 10 文档收敛 + verify-dist | **保留，与 AF2 收尾合并**（→ 阶段 F） | SPEC 收敛正好在 AF2 位级规格合入时一次完成 |
| 明确不做：uniffi-rs、FFI 代码生成 | **维持不做** | 结论未变 |

## 阶段 A：基线与清场（低风险，先行）

**A1. Golden vectors 机制落地**

- 建 `core/testdata/` + Rust 生成器脚本，三端测试断言同一份 fixture；
- v1 覆盖（保留至 v1 删除）：descriptor v1/v3/v5、压缩 none/zstd/xz、单文件/ETTEXT/ETBUNDL、
  分段乱序/重复/缺失、CRC32=0、非法 UTF-8、恶意 bundle 长度、snapshot JSON 样本；
- 预留 AF2 fixture 目录结构（阶段 C 填充）。

**A2. 版本事实源门禁**

- `node scripts/version.mjs check`：以根 `Cargo.toml [workspace.package].version` 为事实源，
  版本位点命中次数精确校验，CI 门禁接入。

**A3. 删除死代码（-750~850 行）**

- 删 `core/transfer-engine/src/assembler.rs`、`resume.rs`、`Error::InvalidResume`、
  `ReceiverSession::save_state/restore`；确认 serde feature 无其他消费者再动依赖；
- `tests/segment_e2e.rs` 不删行为覆盖：改测试内局部拼接辅助器，继续覆盖 descriptor-v5
  校验、段坐标/child session ID、乱序拼接、root SHA-256、压缩后分段单次解压。

## 阶段 B：与协议无关的工程收敛（可与阶段 C 并行）

**B1. 快照化 FFI（三段式，禁止一次性切换）**

- 增量加入 `receiver_snapshot_json`（ingest 排他锁下生成）→ Android → Windows → Web
  逐端迁移 → 删 15+ 旧 getter；
- JNI `AIRFERRY_NATIVE_ABI_VERSION = 2`；C-ABI 增 `airferry_native_abi_version()`，
  Windows 启动校验；快照契约沿用旧计划 `ReceiverSnapshotV1` 字段表；
- `progress_json` 独立不合并；C-ABI 字符串所有权走 `airferry_free_string` 既有模式；
- **设计留缝**：snapshot 带 `schema_version`，AF2 接收器直接发 v2 schema，宿主按版本分发。

**B2. WASM 单轨化（-150~250 行）**

- 统一 `wasm-bindgen = 0.2.92` 标量单产物，Chrome 87 → 最新通吃；
- 原子发布用 symlink 切换（非目录 rename）；
- 同步修改耦合文件：`prepare-wasm.cjs`、`build-all.cjs useWasmPkg()`、
  `pages.yml`、`windows.yml`、`build-fastzxing.sh` 输出路径；
- 构建 target 按 mode 分层（扩展 `["chrome87","firefox91"]` / web 现代 target）。

**B3. FAST-only 强制（-120~220 行）**

- `airferry_zxing.js/.wasm` 缺失即构建失败（不 warn 不降级）；CI 固定 emsdk 3.1.64；
- 卸载 `zxing-wasm` 全部兼容分支（`ensureZxingWasm`/`cropRgba`/RGBA 路径、
  `fastBackendRef`、`zxing_reader.wasm` 拷贝）；
- 补 FAST 回归：单码/四码、1080p、旋转/透视、空白帧、截断图、错误 stride、
  连续坏帧 worker 池自愈。

**B4. 前端 package 合并（-80~150 行）**

- 合并为 `apps/frontend/`：单 package.json + 单 lock；删 `pnpm-lock.yaml`、
  跨目录 alias、重复 `extract-lzma-wasm.cjs`；Plasmo 构建行为不变；同步 CI 路径。

**B5. 全端 CI 构建（新增，后续所有阶段门禁的执行载体）**

- 新建 `.github/workflows/ci.yml`，PR 与 main push 全跑，矩阵覆盖四端：
  - **Rust**：`cargo test`（default + `cffi` + `jni` feature）+ `cargo clippy -D warnings`
    + wasm32 target 编译检查；
  - **Web**：emsdk 3.1.64 固定版 + FAST ZXing 产物构建（缓存 fastzxing 编译产物）、
    `typecheck` / `test` / `build` / `build:receiver` / `build:standalone`；
  - **Android**：`:app:testDebugUnitTest` + `:app:assembleDebug`（缓存 Gradle/SDK）；
  - **Windows**：windows-latest runner 上 `dotnet test` + 完整 `dotnet publish` 构建
    （现有 `windows.yml` 仅发布用，PR 级构建纳入本矩阵）；
  - **全局**：`node scripts/version.mjs check`、golden fixture 三端断言、
    （F4 落地后）`verify-dist.mjs`。
- 要求：任一端红即阻断合并；主路径缓存化使全矩阵 PR 耗时可接受（目标 < 15 min）；
  B2/B4/G 改动构建路径时同步更新本 workflow（列入各步骤耦合文件清单）。
- 落地时机：骨架在阶段 B 建成（先覆盖现状构建），随 C/D/E 各阶段把 AF2 fixture
  与新构建目标增量挂入。

## 阶段 C：AF2 Rust 核心（新模块，不接产品）

协议输入：`docs/protocol/AF2-PROTOCOL-INDEPENDENT-FABLE.md`（以下简称 IF 稿）。
**前置决议**：IF 稿与既有 `AF2-PROTOCOL-FINAL.md` 并存，开工前需逐节对比裁定唯一冻结稿
（关键分歧：OBJECT_META 是否携带 encoded_hash、默认 chunk 8 vs 16 MiB、BLAKE3 vs SHA-256）。

**C1. 帧层与 ID（`qr-protocol/src/frame2.rs` 等新模块）**

- 26B Header + T + 4B CRC32-IEEE 帧编解码；ROOT/OBJECT_META/SYMBOL 三类型；
- BLAKE3-256 哈希域（`blake3` crate，空摘要自检）；
- Content ID / Transfer ID / Object ID 三层派生（含 encoded_hash 绑定）；
- golden vectors：固定小语料的三 ID、单帧字节、ROOT/META 字节各一组，入 `core/testdata/af2/`。

**C2. ROOT / OBJECT_META / Manifest 编解码**

- Root Record（112B + TLV）全部校验规则；Object Meta（112B 含 raw_hash + encoded_hash）；
- Manifest（80B 头 + Entry Records + Chunk Hash Table + TLV）；
- 路径规则完整实现（NFC、禁 `..`/绝对路径/NUL/C0、≤1024B、字节级去重）+ 平台化清洗接口；
- 四作用域 TLV 解析器（critical 位、升序、去重、checked arithmetic）。

**C3. OTI-only RaptorQ 对象**

- 删块表路径：RFC 6330 §4.4.1.2 分区推导，与上游 `raptorq` crate 及 RFC 测试向量交叉验证；
- 删手工符号补零；OTI 全量校验闸门先于建 Decoder。

**C4. Raw Chunk 与压缩（per-chunk）**

- 定长切块（默认 8 MiB，1..32 MiB 2 的幂）；逐块 RAW/Zstd(w≤23)/XZ(≤128MiB) 有界编解码；
- "严格变小才压缩"双端不变量；三 codec × {空、1B、符号边界、chunk 边界、末块} 往返测试；
- 资源攻击测试：恶意 OTI、超长 TLV、路径穿越、解压炸弹、大窗口、大字典。

**C5. 收发状态机**

- Sender：单趟预处理流水线（一次读取完成 entry/chunk/content 哈希 + 压缩候选，
  逐 chunk 多线程并行）、`(路径,size,mtime)` 重发免哈希缓存、自动 playlist
  （Bootstrap → 逐 Chunk → Epoch 循环，17/31 帧控制节奏）；
- Receiver：Idle→Locked→Decode→Ready 状态机、META 前置绑定（object_id 复算）、
  未知 SYMBOL 零缓存、会话失配防抖（≥3 换锁）；
- 账本语义层（bitmap + chunk hash + 提交顺序），宿主存储留接口；
- ingest packed u64 状态字 v2（+manifest_ready / chunk_verified 事件位）。

**门禁**：`cargo test`（含 cffi/jni feature）全绿 + AF2 fixture 三组 + fuzz 帧/TLV/Manifest 解析。

## 阶段 D：AF2 发送端（Web/WASM 先行）

- D1. 压缩 worker 改造：单趟流水线产出 Manifest + chunks；重发缓存落 IndexedDB；
- D2. 播放页改自动 playlist（删除逐段手动切换 UI）；开发构建显式 `AF2` 开关，默认仍发 v1；
- D3. 发送端自测：自动从 Chunk 0 播到 N 并进入下一 Epoch；换 T/codec 重播产生新 Object ID。

## 阶段 E：AF2 接收端（先拆解、后接入）

**E1. 三端控制器拆解（旧步骤 6，AF2 接入的前置）**

- 先固化怪癖为事件序列测试（逐字保留）：`multiMiss % 3 == 0` 全帧解码调度、
  1.5s 静默防抖、17 帧描述符间隔、mismatch ≥3 重锁；
- 分层：CapturePipeline / ReceiveCoordinator（唯一可单测核心）/ TransferMetrics /
  RecoveryService / UI Adapter；
- Windows 试点 → Android → Web；并发规则落为测试与所有权（worker 只投递事件、
  StopAsync 仅 owner 调用、mailbox 替代多锁等，沿旧计划全表）。

**E2. AF2 接收接入（每端一提交）**

- ReceiveCoordinator 挂 AF2 状态机（snapshot schema v2）；
- 账本落地：Android/Windows 稀疏 `.partial` + pwrite/fsync/原子 rename；
  Web IndexedDB/OPFS 事务 + 流式写盘（254 MiB 内存顶随 per-chunk 模型取消）;
- 崩溃注入测试：pwrite/fsync/rename 每个间隙；账本虚报复核；幂等再归档；
- 关键互操作用例：同 chunk 两种编码实例交替播放不混流；换 codec/T 后已完成 Chunk 复用；
  Manifest 后到对暂存 Chunk 复核清位。

## 阶段 F：切换、删除 v1、文档收敛

- F1. 三端互操作矩阵全绿（Web 发 → Android/Windows/Web 收，含恶意输入与断点场景）
  → 一次性切换产品入口为 AF2（不做双协议静默并发，不做自动回退）；
- F2. 删除 v1 构件：`ET` 帧、Descriptor v1/v2/v3/v5、ETTEXT/ETBUNDL parser（三端）、
  Segment v5、旧 ResumeState、旧 FFI getter 残留、v1 golden fixture；
  AF2 端对 v1 全部构件 fail-closed 拒绝并提示"对端版本过旧"；
- F3. 文档收敛（旧步骤 10）：AF2 位级规格合入 `docs/SPEC.md`（唯一线协议事实源，
  并入 protocol/qr-frame-format/raptorq-params）；`architecture.md` 并入 data-flow；
  `BUILD.md` 吸收 dev-setup；`AGENTS.md` 压至 ≤150 行；`perf-web-receiver.md` 移入
  `docs/benchmarks/`；
- F4. `scripts/verify-dist.mjs` 门禁（与 dist-upload-list 并存）：产物完整、manifest 正确、
  FAST WASM 在产物内、APK 非 debug 签名、CRX 固定 key、无 pem/keystore、版本一致。

## 阶段 G：可选尾项（不阻塞发布）

- Vite 替换 Plasmo（旧步骤 8 全部验证清单照抄；接受损失 HMR）；
- chunk_size 策略实测调优、多码 playlist 编排实验、Ed25519/AEAD TLV 扩展预研。

## 每阶段门禁（全绿才进下一阶段）

```bash
cargo test && cargo test -p transfer-engine --features cffi && cargo test -p transfer-engine --features jni
npm run typecheck && npm test && npm run build && npm run build:receiver && npm run build:standalone
cd apps/scanner && ./gradlew :app:testDebugUnitTest :app:assembleDebug
dotnet test apps/windows/AirFerry.Windows.Tests
node scripts/version.mjs check && node scripts/verify-dist.mjs
# golden fixture（v1 + AF2）三端通过
```

回滚策略：每步小 PR 系列，git revert 即回滚；每阶段结束都是可发布状态。
若有版本压力：A、B 任意点可停（仓库净改善）；C、D 不接产品可长期并行；
E 起为切换承诺段，进入后按端逐个收尾。

## 明确不做（关闭反复讨论）

- uniffi-rs（无 C# 后端）；FFI 绑定代码生成（snapshot 后无必要）；
- 双协议长期并存或自动回退解析；符号级 Decoder 持久化；
- 旧步骤 5 ContentManifest 下沉（已废弃，v1 parser 随 F2 整体删除）。
